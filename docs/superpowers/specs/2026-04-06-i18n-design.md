# i18n — Localisation & Translation

## Summary

Add English (EN) and Brazilian Portuguese (PT-BR) support to Transient using `i18next` + `react-i18next` + `expo-localization`. Default language is English. Device locale is detected automatically. Users can manually override language in Settings (persisted to AsyncStorage).

## Stack

- `i18next` — core i18n framework
- `react-i18next` — React hooks (`useTranslation`)
- `expo-localization` — device locale detection

## File Structure

```
lib/i18n/
  index.ts              # i18next init, locale detection, AsyncStorage persistence
  locales/
    en.json             # English translations
    pt-BR.json          # Brazilian Portuguese translations
```

## Translation Key Convention

Flat keys namespaced by screen/domain:

```json
{
  "common.save": "Save",
  "common.cancel": "Cancel",
  "common.delete": "Delete",
  "common.error": "Error",
  "common.yes": "Yes",
  "common.no": "No",
  "common.back": "Back",
  "common.remove": "Remove",
  "common.unknown": "Unknown",
  "login.title": "Transient",
  "login.signIn": "Sign In",
  "login.signInFailed": "Sign in failed",
  "login.noAccount": "Don't have an account?",
  "login.signUp": "Sign Up",
  "tabs.diary": "Diary",
  "tabs.search": "Search",
  "tabs.wishlist": "Wishlist",
  "tabs.stats": "Stats",
  "tabs.settings": "Settings",
  "mediaType.theatre": "Play",
  "mediaType.musical": "Musical",
  ...
}
```

Shared strings (button labels, alert titles, form words) go under `common.*`. Screen-specific strings go under `<screen>.*`. Component-specific display mappings (media types) go under `<domain>.*`.

## Initialisation (`lib/i18n/index.ts`)

1. Import `getLocales()` from `expo-localization`
2. Check AsyncStorage for a saved language override key (`@transient/language`)
3. If override exists, use it; otherwise detect device locale
4. If detected locale starts with `pt`, use `pt-BR`; otherwise use `en`
5. Init i18next with `fallbackLng: "en"`, `interpolation: { escapeValue: false }` (React already escapes)

## Usage Pattern

```tsx
import { useTranslation } from "react-i18next";

function LoginScreen() {
  const { t } = useTranslation();
  return <Text>{t("login.title")}</Text>;
}
```

For alerts: `Alert.alert(t("common.error"), t("login.signInFailed"))`

## Language Switcher (Settings Screen)

Add a language picker (two options: English, Português) to the Settings screen. On change:

1. Save selection to AsyncStorage (`@transient/language`)
2. Call `i18next.changeLanguage(lng)`
3. UI updates reactively via react-i18next

## What Stays Untranslated

- Error messages from Supabase API (dynamic, come from backend)
- User-generated content (reviews, tags, notes)
- Work/production titles (database content)

## Implementation Steps

### Step 1: Install dependencies

```bash
npx expo install i18next react-i18next expo-localization
```

### Step 2: Create translation files

- `lib/i18n/locales/en.json` — extract all ~90 hardcoded strings
- `lib/i18n/locales/pt-BR.json` — translate all strings

### Step 3: Create i18n init module

- `lib/i18n/index.ts` — init i18next, locale detection, AsyncStorage persistence

### Step 4: Wire into app root

- Import `lib/i18n` in `app/_layout.tsx` (side-effect import, before any component renders)

### Step 5: Replace hardcoded strings in screens (14 files)
